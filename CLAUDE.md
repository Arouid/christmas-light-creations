# Christmas Light Creations website

Marketing site for christmas-light-creations.com, a family-owned Christmas light installation business in Pearland, TX. Replaces the old WordPress/X-Theme site on GoDaddy.

## Stack

- React 19 + Vite + Tailwind CSS 4 (`@tailwindcss/vite`), plain JavaScript (no TypeScript)
- Lint: oxlint (`.oxlintrc.json`)
- Static site: public page (`index.html`) + staff Leads page (`leads/index.html`), no router
- Firebase (Firestore + Google Auth) for estimate requests; config in `src/lib/firebase.js`
- Hosted on GitHub Pages, deployed by `.github/workflows/deploy.yml` on push to `main`; custom domain in `public/CNAME`; DNS at GoDaddy. The deploy job's last step pings IndexNow (`scripts/indexnow.mjs`) so Bing recrawls within hours

## Commands

| Command | What |
|---|---|
| `npm run dev` | Dev server on http://localhost:5173 (`.claude/launch.json`) |
| `npm run check` | Lint (zero warnings) + tests + production build |
| `npm test` | Headless tests in `tests/` |
| `npm run check:rules` | Live check that Firestore refuses strangers (anonymous) |
| `npm run build` | Vite build + area pages and sitemap (`scripts/build-areas.mjs`) into `dist/` |

## Working rules

- Run `npm run check` before every commit; don't commit if it fails.
- Commit after each working change, with a clear message.
- After a change, look at it in the browser pane at phone width (375px) and check the console for errors. A passing build doesn't prove the page renders. If the page looks stale, restart the dev server.
- While the dev server runs, write `src/` files with the Write/Edit tools, not shell redirection (`cat > file`): Vite can read the file mid-write and keep serving a broken module ("does not provide an export named …") until restarted.
- Check framework APIs (React, Vite, Tailwind 4, GitHub Pages) against their current docs, not memory.
- Keep `docs/TODO.md` current: add new open items, remove finished ones.
- Tailwind buttons: never add a second `bg-…` to a shared class string (`${btn} bg-glow-400`); the first one can win and the button shows the wrong color. Keep a shape-only class and add exactly one background per button.
- Log what was actually checked in `docs/verified.md` (dated); keep unverified items in `docs/test-checklist.md`; record decisions in `docs/decisions.md`.
- Search positions go in `docs/serp-log.md` (same four searches, same method, one row per check) so the next "vs last month" has a baseline.

## Site rules

- Staff app on desktop (`lg:`): Customers and Season are sortable tables (`DataTable.jsx`), customer detail is a right side panel, sections are a tab row; phones keep lists, a full-screen detail and a ☰ drawer menu (`src/leads/Drawer.jsx`; section lists, shortcuts and groups in `src/lib/staffMenu.js`, tested). A new section goes in `staffMenu.js` (row + a drawer group) or the test fails.
- Area pages: content in `src/data/areas.js`; keep them few and genuinely local (no near-duplicate town pages). Adding one updates the sitemap and homepage links automatically.
- Cost guide `/cost/` (spec `docs/specs/cost-guide.md`): words in `costGuide` in content.js, prerendered (list in `scripts/pages.mjs`, with the sitemap). No dollar amounts on it until the owner fills `costGuide.ranges.rows` (the test refuses them); reuse the home page's `included`, `lightOptions`, `priceBeat` and `lifetimeWarranty` rather than rewording them.
- Mobile first: design for phones, then scale up with `sm:`/`md:`/`lg:`. No horizontal scroll at 375px. Tap targets at least 44px.
- All copy, photos, reviews and FAQ live in `src/data/content.js`. Components hold layout only.
- Images live in the repo under `public/images/` (nothing loaded from the old WordPress CDN). Full-size originals go in `assets-source/`, which isn't shipped; its map (which folder holds what, tracked or ignored, which script reads it) is `assets-source/README.md`.
- Licensed stock (Vecteezy Pro, Envato Elements since 2026-10-14): raw downloads stay in their ignored folders (`assets-source/stock/vecteezy/`, `assets-source/stock/envato/downloads/`), one Elements download is licensed to one named project (re-download from My Downloads for another), never as a logo or trademark, music never for TV/radio or streaming-TV use; the rules and the workflow are in `assets-source/stock/envato/README.md`.
- Colors come from the theme tokens in `src/index.css` (`night`, `glow`, `berry`, `pine`). Fonts: Fraunces (display), Inter (body).
- No analytics scripts and no cookie banners. The one exception is the Google Ads conversion tag (`src/lib/ads.js`, owner decision 2026-10-11): public pages only, never `/leads/`, `/proposal/`, `/account/` or `/invoice/`; disclosed on `/privacy/`. One exception (owner, 2026-10-09): reCAPTCHA Enterprise for Firebase App Check (anti-spam), loaded only with Firebase (`APP_CHECK_SITE_KEY` in `src/lib/firebase.js`); badge hidden, `RecaptchaNote` shown instead.
- Keep the phone number (281-819-0163) one tap away on every screen.
- Service areas: `serviceAreaGroups` in content.js and `areaServed` in index.html must match the Google Business Profile's service areas exactly.
- Don't reword customer reviews; quote them as written.
- Photo captions and alt texts carry the `place` from the `gallery` list in content.js, as the owner named it (his neighborhood-and-town file names on the 2026-10-14 rescans; a contact sheet on 2026-10-13 for the one older photo); never guess a place from a camera file name. Area pages pick photos by file name in `src/data/areas.js` and take caption and alt from that list; a filler from another town keeps its true caption. Hi-res originals live in `assets-source/photos/gallery-hi-res/` (ignored); `scripts/process-gallery.mjs` makes the 1600 px web copies in `public/images/gallery/` (lowercase names, the owner's typos fixed in `FIX`), and `tests/areaPhotos.test.mjs` checks the list and the folder agree. A new photo: drop the original in the hi-res folder, run the script, add its line to `gallery`. The home hero rotates through `heroPhotos` (content.js; each must be in `gallery`): a script at the top of the built page's `<head>` (`src/lib/heroPhoto.js`, inserted by `scripts/prerender.mjs`) picks one per visit before anything downloads; the first one shows without JavaScript.
- IndexNow (spec `docs/specs/indexnow.md`): the key file `public/3bcc247f6ab0920d551117209063808d.txt` (body = its name; public by design) must stay at the site root, and after every Pages deploy the workflow POSTs the sitemap's URLs once to api.indexnow.org (Bing, Yandex, Naver, Seznam; Google ignores IndexNow and reads the sitemap). Best effort, never fails a deploy; no per-page pings from the app.
- Old WordPress URLs must keep redirecting: the `REDIRECTS` map in `scripts/build-areas.mjs` (21 old pages, from the old site's database). Anything else missing shows `public/404.html` (estimate + call buttons).
- Estimate form saves to Firestore `leads`; staff read and update them at `/leads/` (Google sign-in, allowlist in the `staff` collection). Access rules live in `firestore.rules`; any new lead field must be added there and in `LEAD_FIELDS` in `src/lib/firebase.js`. With Firebase not configured, the form shows a call button and `/leads/` shows sample data.
- New Firestore collections need `firestore.rules` republished by the owner (paste in Firebase console). Until then that list is refused; it must not lock staff out (only leads/customers decide access). Say so before shipping a feature that adds a collection.
- Load Firebase with dynamic `import()` only, so the public page stays light.
- Spam (spec `docs/specs/spam-filters.md`): marketing blasts to info@ are dropped by `junkReason` (`functions/messageSync.js`); cold pitches through the estimate form are filed under Spam by `pitchReason` (`functions/pitch.js`), reason in the server-written lead field `spamReason`. Both pure and tested; a new tell goes there, never in the UI. Blocked senders (`settings/app.blockedSenders`, the 🚫 Spam button on unmatched messages, `functions/blocklist.js`) are dropped by the sync before storage.
- Street View on lead cards: `src/lib/streetView.js`. The Maps key is locked to the site's domains + localhost:5173 and to Maps JavaScript, Geocoding and Street View Static APIs (Google Cloud, project clc-leads-site).
- Staff app at `/leads/` has tabs Leads / Customers / Season / Import (spec: `docs/specs/customers.md`). Customers live in Firestore `customers`; ids are name slugs so re-imports update. Use `/leads/?demo` in dev to check the UI with sample data (no sign-in). Importer mapping is pure (`src/lib/importSheet.js`) and tested in `tests/`.
- `/leads/` is `noindex` and disallowed in `robots.txt`; never link it from the public site.
- AI training crawlers are turned away (owner 2026-10-13): the AI group in `public/robots.txt`, `public/ai.txt`, `public/.well-known/tdmrep.json`, `LICENSE`, and `<meta name="robots" content="… noai, noimageai">` on every page (area and redirect pages get it from `scripts/build-areas.mjs`). A new HTML page gets the meta too. Search and answer bots stay allowed on purpose (owner: "unblock any that might be used for searching our business"): Googlebot, Bingbot, OAI-SearchBot, ChatGPT-User, Claude-SearchBot, Claude-User, Perplexity, Google-Extended, DuckAssistBot, Meta-ExternalFetcher, Amazonbot; the list in robots.txt says which and why.
- Privacy page `/privacy/` (words in `privacy` in content.js) must stay true: when the site starts collecting or sharing something new, update it in the same commit.
- Staff notes (spec `docs/specs/notes.md`): `notes/{id}` is private to its writer unless `shared`; the app reads two queries (`by == me`, `shared == true`), never the whole collection, because the rules only allow those. My checklist on Home is `src/lib/checklist.js` (device ticks, period keys).
- Customer emails: every one goes through `functions/brand.js` (`branded`/`brandText`, logo header, spam line; `optional: true` only on weather heads-ups and tips, which customers may turn off on `/account/` → Email preferences; agreements, bills, reminders and scheduling never have a switch). Automatic sends ("Got your request", the hourly staff nudge, the 4:30 pm weather watch, the 4 pm Google review ask) have switches in ⚙ Settings → Automatic emails and are specified in `docs/specs/auto-emails.md`. The review ask (`functions/reviewAsk.js`, spec `docs/specs/review-ask.md`) asks everyone the same way 2 days after Install Completed with one reminder, never offers anything and never texts (a ⭐ item in 💬 for a person instead); past customers also see one ★ card on `/account/` (`accountReview`, words `accountReviewCard` in content.js) until They reviewed; the review link is `REVIEW_URL` in `functions/brand.js`, imported everywhere, never retyped. Things customers must be told plainly (trees) live in `functions/notices.js` and are reused, never retyped.
- Staff guide (the ? button in the staff app): content in `src/leads/guide.js`. When a staff feature is added or changes, update the guide in the same commit (and its `GUIDE_UPDATED` date).
- Customer accounts at `/account/` (noindex, robots-disallowed): Google, email-link or phone-number sign-in (never grants staff access); data only via the `myAccount` function (records whose `emailKeys` hold the verified email, any case, or whose `phoneKeys` hold the token's `phone_number`), payments via the same PayPal callables. Phone sign-in (spec `docs/specs/phone-sign-in.md`): Firebase sends and checks the code (invisible reCAPTCHA verifier, no code of our own); `phoneKeys` are kept by the same server triggers and lazy index fill as `emailKeys` (`functions/phone.js` for E.164), so a new place that writes `emailKeys` writes both. `myAccount` also records sign-ins in `customerLogins/{email or E.164 phone}` (server-only writes, staff read) for the Accounts page, and returns the yearly-price breakdown (`src/lib/addOns.js`, spec `docs/specs/add-ons.md`) only when staff set `priceShown`. `/account/?demo` in dev shows sample data. It is also the customer app (spec `docs/specs/customer-app.md`): `public/account/manifest.webmanifest`, `sw.js` (caches only `offline.html`), icons from `scripts/make-account-icons.mjs`; the Google Play app is a Trusted Web Activity of this same page, so never move or rename `/account/`. The account also shows this season's schedule (from the season fields staff fill in) and takes problem reports (spec `docs/specs/account-service.md`): reports go only through the `reportProblem` callable, which writes `serviceCalls` with `source: 'customer'` (one open call per customer), logs `service-reported`, and alerts staff like a new message; 💬 reads them from `serviceCalls`, never from `messages`. Staff preview (spec `docs/specs/account-preview.md`): 👁 View their account opens `/account/?preview=<customer id>`; the staff-only `accountPreview` callable returns the same payload as `myAccount`, both built by `accountFor` + `accountPayload` (`functions/accountPayload.js`, whose field lists are what Firestore is asked for: a field the page starts reading goes there), reads only (never `recordLogin`); on the page every action is greyed out and nothing is kept on the device. House picture (spec `docs/specs/account-house-photo.md`): under the greeting, our 🏠 `housePhoto` through a 1-hour signed link that `accountFor` makes (`houseLink`, only a file in that customer's own folder: `housePhotoFile`, tested), else Street View of the address, else nothing; Storage rules stay staff-only and the stored staff download link is never sent.
- Invoices (spec `docs/specs/invoices.md`): `invoices/{link token}`, customer page `/invoice/?t=` (noindex, robots-disallowed, `?demo` in dev), staff Invoices tab. Totals, states, numbers, reminders and season fills live in `functions/invoices.js`, shared by the server and the pages (via `src/lib/invoices.js`): change them there only. Only the server writes the number, online payments, emails sent and season bookkeeping; staff only Mark paid for offline money.
- Sales tax (spec `docs/specs/receipts.md`): `src/lib/salesTax.js` reads `settings/app.salesTax` (rate, permit, start date; owner: 8.25% from 2026-10-15). Proposals carry `tax` + per-line `taxable`; invoices carry `tax`. The math lives in `totals()` (`src/proposals/model.js`), `functions/proposalMath.js` and `functions/invoices.js` (`invoiceCents` = lines + tax) only; keep the three in step (tests). Older proposals have no `tax` and must keep their fingerprints.
